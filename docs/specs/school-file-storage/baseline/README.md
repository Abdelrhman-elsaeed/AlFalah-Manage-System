تم تنفيذ نطاق S0 باستخدام skill `dotnet-layered-api-architect`: مراجعة المسارات وحدود الخدمات والمستودعات، وتسجيل الفروق اللازمة للمراحل التالية. لا توجد migrations أو تغييرات في كود المنتج أو بيانات SQL أو ملفات Drive. لم يُشغّل البروتوتايب أو خادم API. لم تبدأ S1.

تواريخ الموارد وبصماتها في سجل المصدر، وتاريخ الالتقاط في JSON. `literalLocations` بحث نصي فقط وقد يجد 4116 داخل اسم/مسار؛ المرجع الدلالي للأرقام هو الجدول أعلاه، وليس عدد مرات ظهور النص.

لم يوجد أصل بايتات لأي من 4617 مرجعًا في الفهرس أو 145 مرجعًا بالمصفوفة تحت BASE_DIR الفعلي. هذا الجذر هو **الأب** لمجلد core الداخلي وفق app_server.py، وليس مجلد core نفسه. لم نبحث خارج حدود الحزمة أو نستنتج غياب الملفات من Drive. الحزمة تملك واجهات وتقارير ووسائط مرجعية؛ غياب أصول الشواهد لا يعني غياب هذه الموارد.

## فروق المصدر المؤثرة

1. عناصر عرض المتتبع والمصفوفة التي يبحث عنها JavaScript غائبة عن الرئيسية؛ صفحة المصفوفة المستقلة تحتوي عناصرها. جدول المطابقة يحتفظ بوظائفهما المطلوبة مع هذا الفرق.
2. JSON المصفوفة: 89 مسارًا مميزًا، 56 تكرار مسار، 46 صفًا مكررًا تمامًا، و56 تصنيفًا لا يظهر في المسار. matrix192Data: 145 مسارًا مميزًا؛ لا تساوي JSON. S6 يطلب تسوية المصدر في preview، ولا يضاعف مطالب الاستيفاء اعتمادًا على أعداد الصفوف.
3. كل 145 صفًا في JSON مصنف «مكتمل ومستوفى» وكل 36 بندًا completed رغم غياب الأصول. هذه الحالات تحفظ كبيانات تاريخية فقط ولا تُعتمد في النظام الجديد.
4. فهرس المعايير يشمل 1.5 «حقوق المتعلم وحمايته»؛ المتتبع له 10 رموز مميزة، ويضع آخر بندين تحت 2.2. خريطة المجال تحفظ 1.5 وتسجل غياب بند متتبع له.
5. الفهرس يحتوي أنواعًا أخرى لم يعتمدها المستخدم للرفع الجديد: ACCDB/JFIF/MD/PPS/PPTM/RAR/TSCPROJ/URL/WAV/XLSM/ZIP وامتداد فارغ/غير معتاد. تُعرض كمراجع تاريخية/استثناء نوع؛ وجودها في الفهرس لا يوسع قائمة رفع S2 تلقائيًا.

## القياس المحلي وDrive

SQL Development: 18 مدرسة إجمالًا، 3 غير محذوفة، اتصال واحد مفعّل، مجلد معلم نشط واحد، شاهد واحد مسجل Approved/Completed، 31 مهمة، سنة واحدة، صفر عمليات رفع Pending. السجل يحمل شاهدًا غير محذوف ولا missing flag؛ لا يثبت ذلك وجود ملفه الآن.

محاولة مراقب Drive استخدمت الخدمات الحالية دون تشغيل التطبيق أو reconciliation. توقفت عند فك تشفير credential بالمفاتيح الحالية، قبل أي HTTP request (عدد الطلبات 0). لذلك عدد الملفات والمجلدات وغير المفهرس في Drive **غير متاح**. لم تُعد كتابة الاتصال أو مفاتيح Data Protection. إعادة القياس تتطلب اتصال Development قابلًا لفك التشفير بالمفاتيح الصحيحة، ثم تشغيل المراقب؛ لا نطلب تغييره أثناء S0.

## التحقق المنفذ

- تشغيل جرد Python من المصدر وتأكيد بصمات الموارد قبل/بعد القراءة؛ ثبتت الأعداد والمخططات وفروق DOM والتكرارات.
- تشغيل PowerShell SQL collector بالـ SELECT فقط؛ قراءة محلية مباشرة بلا startup أو migrations/seed.
- بناء مراقب Drive: `0 Warning(s), 0 Error(s)`، ثم تشغيله بـ `--roll-forward Major` لأن الجهاز يملك ASP.NET Core 10 ولا يملك runtime 8. هذا خاص بأداة القياس ولا يعدل استهداف التطبيق. النتيجة Unavailable موثقة، وليست نجاح اتصال.
- مطابقة مجموعة أسماء دوال الرئيسية الـ92 مع صفوف parity؛ لا اسم مصدر ساقط من الجدول.
- مراجعة الروابط المحلية و`git diff --check` قبل حفظ التغييرات. سيناريوهات UI/API الجديدة في parity تخص مراحلها ولم تُنفذ في S0.
