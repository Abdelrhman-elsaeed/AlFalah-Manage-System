# S2 — مكتبة المدرسة وملف المعلم والرفع الآمن

- **الحالة:** نُفذت S2 تقنيًا؛ SQL معزول وAngular/متصفح محاكاة؛ رايات OFF، والتحقق الحي وcutover معلّقان بقيد S0
- **الاعتماد:** مخطط وصلاحيات ونتيجة backfill من [S1](01-foundation-and-permissions.md)
- **النتيجة:** مكتبة قابلة للاستخدام للمدير/المفوّض وواجهة ملفات المعلم، دون احتساب شواهد جديدة قبل S3

## هدف المستخدم

المدير والمفوّض يتصفحان شجرة ملفات المدرسة العامة ويرفعان إليها؛ المعلم يتصفح مجلده الممنوح ويرفع ملفه ويرى تاريخه فقط. الملف الجديد يحصل على سجل metadata ونسخة واحدة في SQL وعنصر واحد في Drive. فشل اتصال Google أو تكرار الطلب لا يخلق ملفًا مكررًا أو مؤشر نجاح كاذب.

## نطاق backend

1. وسّع عميل Google الحالي خلف adapter واضح (`IStorageProvider` أو واجهة محددة) لإنشاء مجلد، رفع stream، metadata، قراءة محتوى، rename/trash، والتحقق من ancestor/root. لا تضع قواعد الهوية أو المراجعة داخل عميل Google.
2. خدمة المكتبة تتحقق من المستخدم، المدرسة، نوع الجذر (`School`, `Teacher`, `VisitArchive`)، علاقة المجلد بجذر المصرّح، وقواعد `Storage.ManageSchool`/`Storage.ManageOwn` قبل كل عملية. مدخلات `parentFolderId` معرفات داخلية؛ لا تقبل `DriveId` أو `RootItemId` من عميل المعلم.
3. `GET /api/v1/storage/folders` و`GET /api/v1/storage/files/{id}` و`GET /api/v1/storage/files/{id}/content` تقدم شجرة وبطاقات وتفاصيل وبثًا آمنًا؛ قوائم المجلد والبحث العام paginated في SQL/Drive حسب الحالة، مع حدود صريحة لحجم الصفحة وفرز ثابت.
4. `POST /api/v1/storage/me/files` ورفع المدرسة العامة يدعمان `Idempotency-Key`، التحقق من الامتداد ومحتوى النوع والحجم، اسمًا آمنًا، stream بدلاً من تحميل البايتات كلها في الذاكرة، وحالات عملية Pending/Completed/Failed. لا تعُد رسالة نجاح إلا بعد تثبيت معرف Drive وسجل SQL.
5. في حالة نجاح Drive وفشل حفظ SQL، احفظ العملية القابلة للمصالحة ولا تبدأ رفعًا ثانيًا تلقائيًا لنفس المفتاح. reconciliation يبحث عن العنصر ويربطه أو يعلّمها `NeedsAttention`؛ في حالة غياب ملف من Drive لا يبقى قابلًا للتحميل.
6. إعادة التسمية والحذف قبل الاعتماد فقط طبق حالة روابط الملف. حتى قبل S3 تُعامل submission القديمة المعتمدة كملف معتمد. الحذف منطقي في SQL وتديره سياسة احتفاظ Drive؛ لا تحذف أصلًا تاريخيًا لازمًا للمراجعة. إنشاء/نقل مجلد يتحقق من عدم دورة الشجرة ومن حدود المدرسة.
7. أبقِ `teacher-drive` و`teacher-drive-admin` متوافقين عبر خدمة مشتركة، ولا تترك كاتبين مستقلين لسجل الملف. إن ظهر عنصر Drive بلا ledger يعرض «غير مفهرس» داخل نطاقه ولا يدخل التقارير؛ أتح مسار فهرسة/ربط لاحقًا للمصرح.

## واجهة Angular

- صفحة المدير `/school-manager/storage`: رأس سياق المدرسة والسنة، شجرة مجلدات قابلة للطي، breadcrumbs، بحث ضمن المجلد/عام، فرز، صفحات، عرض قائمة/بطاقات، منطقة رفع بالسحب، لوحة تفاصيل ونسخ وحالة Drive. تظهر إجراءات ملفات المدرسة العامة للمدير/المفوّض فقط.
- ملف المعلم في المسار الحالي أو `/instructor/my-files`: ملفاته هو فقط، المجلد الممنوح، رفع وتقدم وإلغاء قبل الإرسال، آخر الملفات، حالة «الاتصال غير متاح»، ورسالة لا يوجد مجلد ممنوح. لا تعرض شجرة المدرسة العامة.
- المعاينة PDF/صور/وسائط مسموحة داخل المتصفح بعد طلب API مصرح؛ صيغ Office غير القابلة للمعاينة تحصل على تنزيل/رسالة واضحة. الرابط المنسوخ رابط داخلي يحتاج تسجيل الدخول، وليس رابط Google عامًا أو مسار Windows.
- تبنّي shell/RTL وألوان المنصة وPrimeNG، تفاعل لوحة المفاتيح وaria labels وحالات loading/empty/error، مع تصميم سطح مكتب وهاتف وأداء مع آلاف العناصر. لا تكرر HTML البروتوتايب أو أسماءه الثابتة.

## العقود والحدود

استخدم DTO منفصلًا للقائمة والتفاصيل والرفع والمجلد، و`ApiResponse<T>` لـ JSON و`File` للبايتات. يجب أن تعيد استجابة الرفع `storedFileId`, `versionId`, `status`, `displayName`, `size`, `mimeType` ووقت الرفع دون معرفات Drive الخام للمعلم. استجابة القائمة تميّز `Managed`, `Unindexed`, `MissingFromDrive`؛ لا تُفهم `WebUrl` أنها تصريح عام. اربط Angular guards بالصلاحيات، مع تحقق backend حاسم.

## خطوات العمل المقترحة

1. adapter وجذر مدرسة محمي وإدارة مجلدات بدون رفع، مع اختبارات ancestor/cross-school.
2. عمليات الرفع والفهرسة/reconciliation واختبارات idempotency وفشل SQL/Drive.
3. endpoints القراءة والمحتوى والبحث والترقيم، ثم التوافق مع controller القديم.
4. الواجهات مع الحالات الفارغة/الأخطاء، والتحقق في متصفح عربي على الهاتف والسطح.

## بوابة القبول

- مدير ومفوّض يرفعان ملف مدرسة عامًا؛ معلم لا يستطيع ذلك أو رؤية جذر المدرسة/زميله حتى عبر معرف مباشر. المفوّض يفقد الوصول فور سحب التفويض.
- إعادة إرسال نفس upload key بعد انقطاع الشبكة تنتج عنصر Drive وسجلًا واحدًا؛ فشل Drive لا ينشئ ملفًا معدودًا ناجحًا.
- يمكن البحث والتصفح والتنزيل المصرح لآلاف العناصر بترقيم من الخادم؛ تتحقق القياسات على بيانات مماثلة للإنتاج ويُسجل زمن القوائم الفعلي.
- الواجهة القديمة لا تتراجع، ولا يُحتسب ملف غير مفهرس أو مفقود كشاهد. بعد توثيق النتائج وتحديث سجل المرحلة يمكن بدء [S3](03-evidence-and-review.md) بتكليف مستقل؛ طلب التنفيذ الحالي يقف بعد S2.

## نتيجة التنفيذ — 2026-10-03

نُفذت بنود backend وواجهتا `/school-manager/storage` و`/instructor/my-files` داخل shell وRTL. [تقرير S2](../verification/s2-library-and-uploads.md) يحفظ العقود، الاختبارات، قياس الأداء، حدود المعاينة، التوافق القديم، المصالحة، والتفعيل/الرجوع. البحث والترقيم في SQL؛ اكتشاف Drive بصفحات 25 يوسم الملف بلا ledger «غير مفهرس» دون إتاحته للتنزيل أو احتسابه. إنشاء/نقل المجلد للمدير/المفوّض؛ المعلم يتصفح منحة مجلده فقط. لا تطوير للربط المتعدد أو المراجعة أو تغيير النسخة أو الأرشفة أو الاستيراد في S2.

بوابة التشغيل الحية **غير مستوفاة**: بيانات اعتماد Development لا يمكن فكها بالمفاتيح الحالية حسب S0. لم تتغير بيانات الاعتماد ولم تُفعّل رايات Storage؛ لا كتابة Google فعلية ولا ادعاء بقياس Drive حي. اختبارات المتصفح تستخدم API محاكاة؛ الأداء المسجل SQL محلي وخدمة مع Drive بديل. أصل Development لم يُهاجر. التوقف بعد S2؛ S3–S6 لم تبدأ.
