# S6 — الاستيراد التاريخي والتحقق والإطلاق

- **الحالة:** محددة، لم يبدأ التنفيذ
- **الاعتماد:** نتائج [S0–S5](../plan.md)، وقالب المجالات والبنود الذي أصبح تشغيليًا في S4
- **النتيجة:** استيراد قابل للإعادة، تجربة تشغيل قابلة للرجوع، وتقرير parity نهائي

## فصل البيانات المرجعية عن الأصول

المصدر المتاح يحمل فهرسًا فيه 4617 سجلًا، مصفوفة فيها 145 صفًا، ومتتبعًا فيه 36 بندًا، بينما بعض شاشات وتقارير HTML تعرض 4116 أو 4994. هذه سجلات مرجعية متباينة؛ لا يُسمح لعملية الاستيراد بأن ترفعها كملفات حية أو تضعها في بسط الجاهزية دون وجود البايتات الأصلية والتحقق منها. S4 زرع القالب المنقح للمجالات والمعايير والبنود اللازمة لتشغيل الميزة؛ S6 ينشئ **أداة الاستيراد والمطابقة** للبيانات التاريخية المتاحة الآن والملفات الأصلية إذا وصلت لاحقًا.

## خط الاستيراد

1. أدخل ملفات المصدر عبر أداة إدارية محصورة بالمدير/المفوّض أو مشغّل مخوّل بحسب سياسة المدرسة؛ لا تشغّل سكربتات أو executable البروتوتايب. احفظ بصمة المصدر ونسخته ووقت/فاعل الاستيراد في `PrototypeImportBatch`.
2. `preview` يقرأ JSON/CSV بحدود حجم وعمق وقيم آمنة، يعرض المدارس/السنوات/المجالات/المعايير/البنود والصفوف الجديدة/المتطابقة/المتعارضة/الناقصة، ويكتب `PrototypeImportRow` بتصنيف واضح. لا يغيّر أي بيانات تشغيلية.
3. طابق أكواد المجالات والمعايير مع القالب S4، ومسؤوليات الأشخاص مع هوية مستخدمين حقيقية بعد مراجعة. لا تعتمد أسماء HTML الثابتة كمعرّف مستخدم. يحتفظ الصف الأصلي بالمسار والاسم/الحجم والامتداد كمرجع provenance دون إدخال مسار Windows كوجهة على الخادم.
4. `commit` idempotent على `(source hash, source row key, school, year, template version)`، يحدّث القالب/المهام القابلة للإدارة وفق preview المعتمد ولا يكررها. التصادمات التي قد تمس قوالب مستخدمة في سنة منشورة تحتاج إصدار قالب جديد أو قرار مسؤول، لا تعديلًا صامتًا للماضي.
5. عندما تتوفر البايتات القديمة: طبّق pipeline منفصلًا للتحقق من الملف، المسار، الحجم، الامتداد، البصمة، الكشف عن التكرار، المدرسة والصلاحية. اعرض مطابقة `file ↔ reference row` ومشاكل الغياب/التكرار للمراجعة البشرية قبل الرفع. ثم ارفع إلى Drive الخاص بالمدرسة مع idempotency وسجل `StoredFileVersion` واربطه فقط بمتطلب مؤهل؛ الاعتماد التاريخي لا يُختلق من صف يقول «مكتمل» وحده.
6. صف بلا أصل أو صف فشل مطابقته يحتفظ بحالة `ReferenceOnly`/`NeedsReview` وتقارير استثناءات قابلة للتصدير؛ لا رابط تنزيل ولا عداد ملف حي. لا تستخدم طرق Windows للفتح في المنتج.

## التحقق الشامل قبل الإطلاق

- شغّل جدول parity من S0: كل وظيفة لها شاشة/عقد واختبار أو فرق موثق. جرّب المدير والمفوّض والمعلم على الهاتف والسطح، بالعربية RTL، بما فيها البحث والتصدير والمراجعة وطلبات التغيير وحالة Drive.
- اختبر عزل المدرسة وملكية المعلم والتفويض المسحوب بمخاطبة endpoint مباشرة؛ لا يكفي اختبار guards. افحص منع public Drive links ومسارات الخادم وتدقيق التنزيل.
- قارن backfill والجداول القديمة مع الجديدة على عينة فعلية حسب المدرسة/المعلم/السنة/المهمة، ثم قارن إجماليات الملفات الفريدة والروابط والمتطلبات. وثّق الفروق المتوقعة، ومنها الأرقام المرجعية 4116/4617/4994.
- نفّذ سيناريو توقف worker أو Google أثناء أرشفة زيارة واعتماد تلقائي/يدوي، ثم recovery دون تكرار. أعد استيراد المصدر مرتين وأثبت عدم تكرار القوالب أو الملفات.
- قِس الأداء على آلاف العناصر والتصديرات ومولد PDF؛ أصلح مخاطرة مثبتة بالقياس فقط، ثم سجّل الحدود التشغيلية في runbook.

## خطة التفعيل والرجوع

1. أبقِ واجهات/جداول الملفات القديمة متاحة أثناء pilot خلف feature flag، وفعّل مدرسة تجريبية أو مستخدمين مخولين بعد نسخ احتياطي واختبار restore.
2. تحقق من عدم وجود كاتبين مستقلين لحالة المراجعة عند cutover: endpoints القديمة والجديدة تستدعيان خدمة القرار نفسها. سجّل وقت التحول ومنفذه وخريطة التوافق.
3. راقب أخطاء upload/reconciliation/outbox، الملفات غير المفهرسة، روابط معتمدة لملفات مفقودة، زمن الجاهزية، واختلاف مجاميع التقرير. عرّف عتبات تنبيه وخطوة تصحيح لكل حالة.
4. عند الرجوع: أغلق واجهة/قراءة الميزة الجديدة بالـ flag، احتفظ بالبيانات الجديدة وعمليات الأرشفة في حالة آمنة، ولا تعكس migration بإسقاط الجداول أو تحذف ملفات Drive. وثّق معالجة الكتابات التي وقعت أثناء pilot قبل إعادة فتح القديم.
5. أرشف تقرير قبول يتضمن نتائج الاختبارات، parity، استثناءات الاستيراد، موافقة المسؤول على بيانات المدرسة التجريبية، وخطة تشغيل العامل والمراقبة.

## بوابة الاكتمال

- استيراد نفس المصدر مرتين لا يضاعف المجالات أو المعايير أو الـ 36 بندًا، وكل واحد من 145 صفًا له حالة استيراد/استثناء قابلة للتتبع.
- الصفوف المرجعية بلا بايتات تظهر «مرجع فقط»، ولا تدخل عداد الملفات الحية أو جاهزية المدرسة. عند توفر أصول قديمة، لا يصبح أي ملف شاهدًا معتمدًا دون مراجعة فعلية.
- كل وظيفة متفق عليها في البروتوتايب منقولة أو لها فرق مقبول موثق؛ الفروق المرئية مثل حذف فتح Windows المحلي لها بديل ويب واضح.
- صلاحيات المدارس، المراجعة والنسخ، الأرشفة، والتصدير تمر باختبارات قبول عابرة للأدوار؛ خطة rollback وrestore جُربت في بيئة تجريبية.
- تحديث [الخطة الرئيسية](../plan.md)، [سجل المرحلة الجامع](../../../phases/PHASE-SFS-SCHOOL-FILE-STORAGE.md)، وREADME/القرارات بعد التشغيل، مع تقرير نهائي بالقيود المتبقية. لا يتم تقاعد أي جدول أو ملف تاريخي ماديًا ضمن هذه المرحلة.
