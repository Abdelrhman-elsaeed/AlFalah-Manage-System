# اختيار مجلد الحساب وتجهيز تجربة المدرسة — 2026-10-05

بتوجيه المالك استُخدمت مدرسة الاختبار الموجودة، وأضيف استعراض حساب Google واختيار مجلد المدرسة بدل إدخال معرّفه يدويًا. هذا العمل تجهيز للربط والتجربة الحية؛ أداة الاستيراد التاريخي S6 والإطلاق وcutover لم تُنفّذ ضمنه.

## السلوك والعقود

المسار ثلاث خطوات: حفظ اتصال غير مفعّل دون اشتراط مجلد، موافقة Google، ثم استعراض الملفات واختيار مجلد وحفظه. يمكن استيراد OAuth Web JSON من الجهاز بدل نسخ بياناته يدويًا. لا تُحفظ الأسرار في browser storage أو تُعاد في DTO؛ الحقول تُمسح بعد الحفظ وتغيير المدرسة. حالة «بيانات محفوظة» مستقلة عن «حساب مربوط» وعن «مفعّل».

`GET /api/v1/school-google-drive/folders` يعرض أسماء الملفات والمجلدات، breadcrumbs، بحثًا داخل المجلد الحالي وصفحات من 50 عنصرًا. الملفات تُعرض ولا تُختار كجذر. يقرأ `ActiveSchoolId` فقط، ويتحقق من المستخدم والمدرسة والدور المباشر الفعلي من SQL قبل وبعد Google I/O. لا يمنح تفويض التخزين صلاحية إعداد الحساب. API وطلبات الإعدادات ترجع أخطاء محلية للصفحة، و403 يمسح الحالة المعروضة.

المجلد المختار يتحقق منه الخادم، بما فيه الاسم الحقيقي و`driveId` و`capabilities.canAddChildren`. يمنع اختيار My Drive كله، الملف، المحذوف، المجلد غير القابل للكتابة، منحة المعلم، الجذر المتداخل مع مدرسة أخرى، أو استبدال جذر يخرج منح المعلمين وجذور المكتبة/الأرشيف الحالية. الجذور الأجنبية لا تظهر في النتائج ولا يمكن دخول شجرتها بمعرّف مباشر. خدمة setup تملك metadata/list فقط؛ setup token لا يسمح باستخدام اتصال معطل في مسار التشغيل العادي. قبل تطبيق S1 تُقرأ الحدود القديمة دون محاولة الاستعلام من جداول التخزين غير الموجودة.

مراجع Google الأولية: [Web server OAuth](https://developers.google.com/identity/protocols/oauth2/web-server)، [Files metadata/capabilities](https://developers.google.com/workspace/drive/api/reference/rest/v3/files). ملف OAuth Web يحتوي بيانات العميل؛ refresh token ينتج من موافقة صاحب الحساب.

## ما تغير في البيئة المحلية

شُغّلت أداة [DrivePilotSetup](../scripts/DrivePilotSetup/Program.cs) أولًا dry-run ثم apply بتكليف المالك. المدرسة الفعلية `18 / Al-Falah E2E Test School`، ومديرها الحالي `admin.test`. حفظت OAuth client secret مشفّرًا باستخدام مفاتيح Data Protection الموجودة، مع بريد الحساب الذي قدمه المالك. الاتصال غير مفعّل، دون refresh token أو مجلد. ملفات الاعتماد وبياناتها لا تدخل المستودع.

هذه كتابة مقصودة لصف اتصال المدرسة وسجل تدقيق فقط؛ لا migrations أو seeding أو تبديل مفاتيح أو تعديل appsettings. تقارير S0–S5 السابقة تصف حالة البيئة وقت تنفيذها؛ عبارة «credentials unchanged» فيها لا تشمل هذا الإعداد اللاحق.

الـAPI الأصلي على 5264 لم يُستبدل: المراجعة التلقائية رفضت أمر إعادة تشغيله برسالة `blocked by policy` دون تفصيل السبب. استُخدم API مؤقت على 5265 للتحقق الداخلي، مع `Database:InitializeOnStartup=false` والرايات الأربع OFF. Google redirect المصرح به في JSON هو 5264، لذلك تجربة الموافقة الحية تحتاج تشغيل النسخة الجديدة هناك باستخدام [start-drive-pilot.ps1](../scripts/start-drive-pilot.ps1). السكربت يرفض منفذًا مستخدمًا ولا يوقف أي عملية؛ يخصص إعدادات البيئة للعملية ويستعيدها بعد الخروج. خيار تعطيل startup migrations/seeding متاح في Development فقط؛ سلوك الإنتاج الافتراضي محفوظ.

## التحقق والحدود

- جميع اختبارات backend: **896 نجحت، صفر فشل/تخطي** على SQL جديد معزول. أضيف بعد ذلك اختبار خطأ business عند غياب موافقة Google؛ مجموعة الاختبارات المعنية النهائية **59 نجحت، صفر فشل/تخطي**.
- اختبارات Angular: **57 نجحت**، بما فيها النقل والإعدادات والتخزين وV2 والتنقل.
- Playwright: **12 نجحت** على desktop/mobile بعقود API محاكاة: استيراد JSON، حفظ draft، اختيار/حفظ، بحث ومسار، pagination، رفض اختيار، سحب صلاحية، وملف غير صالح. لا تعتبر هذه Google live QA.
- build الإنتاج للواجهة نجح؛ توجد تحذيرات CSS budget/selectors قائمة في مكونات أخرى.
- HTTP مع SQL المحلي الفعلي: إعدادات 18 وauth-url يرجعان **200**، والأسرار غائبة، وauth-url يطابق callback المحلي. طلب الاستعراض قبل consent يرجع **400** برسالة ربط الحساب دون Google HTTP. سكربت التشغيل فُحص نحويًا، واختُبر رفض المنفذ المستخدم دون إيقاف العملية الأصلية.

لا طلب Google حي ولا upload/share/delete، ولا استقبال OAuth callback فعلي، ولا اختيار مجلد حقيقي. الأصول التاريخية لم تُستورد. الرايات `AdministrationEnabled`, `ReadModelEnabled`, `ArchiveWorkerEnabled`, `ArchiveExternalWritesEnabled` تظل OFF. لا تُفعّلها تجربة إعداد الاتصال تلقائيًا. نتيجة الاختبارات التفصيلية وحالة التجربة في [drive-settings-checks.json](drive-settings-checks.json).

## إكمال التجربة

1. تم تنفيذ إعادة تشغيل الـAPI والواجهة بطلب صريح لاحق من المالك في 2026-10-05. لإعادة التشغيل مستقبلًا، أوقف الـAPI من طرفيته ثم شغّل `powershell -NoProfile -File docs/specs/school-file-storage/scripts/start-drive-pilot.ps1` من جذر المستودع.
2. افتح `http://localhost:4200/school-manager/evidence-settings` بحساب مدير مدرسة الاختبار، واختر المدرسة 18 إذا كانت الجلسة متعددة المدارس.
3. اضغط ربط Google، ووافق بحساب الاختبار الذي قدمه المالك. اختر مجلدًا مخصصًا للمدرسة من «اختيار مجلد من الحساب»، ثم احفظ.
4. يلزم بعدها التحقق الحي من الرفع/التحميل والصلاحيات قبل أي إقرار تشغيل S6. الرجوع يغلق الاتصال والرايات ويحفظ التاريخ؛ لا حذف مجلدات أو مفاتيح أو migrations.

بعد التقرير الأول طلب المالك صراحة إعادة تشغيل التطبيق. أُوقفت عمليتا الـAPI وAngular بعد مطابقة هويتهما ومسار المستودع، ثم شُغّلت النسخة الجديدة على 5264 والواجهة على 4200 في الخلفية. احتفظ التشغيل بإعدادات منع startup migrations/seeding والرايات الأربع OFF. صفحة الإعدادات وإعدادات المدرسة 18 وauth-url رجعت 200، وcallback المحلي طابق الملف المسجل؛ استعراض الحساب قبل موافقة Google رجع 400 كما هو متوقع. الـAPI الحالي يعمل بالنسخة الجديدة؛ الموافقة الحية ما زالت خطوة صاحب الحساب. حالات عدم استبدال الـAPI في التقرير أعلاه تخص المحاولة السابقة فقط.
