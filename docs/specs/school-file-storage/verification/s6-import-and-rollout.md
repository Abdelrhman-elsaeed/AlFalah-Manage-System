## Import behavior and contracts

`/school-manager/storage/imports` implements Arabic RTL source selection → preview → mappings → explicit review → commit → paged results/exception CSV → separate original-byte upload/reconciliation. API contracts are under `/api/v1/storage/imports`; every call checks live SchoolScope, active DB role/membership, and `Storage.ManageSchool`. Both AdministrationEnabled and ReadModelEnabled must be ON in an authorized environment. Cross-school/teacher and revoked-delegation checks are server checks, independent of guards.

Preview accepts inert UTF-8 JSON/CSV only: 16 MiB, 10,000 rows, JSON depth 16, 32 columns, keys 128 characters, names 512, paths 2048. Duplicate keys, invalid sizes/scalar rows/executable extensions are rejected. No JavaScript, shell, source scanner or Windows path is executed. Supported source aliases cover the actual index (`mainDomain`, `standard`, `fileName`, `relPath`, `sizeBytes`, `ext`), matrix (`name`, `rel_path`, `category`, `role`, `status`) and tracker (`id`, `doc`, `domainKey`, `responsible`, `targetRelPath`, `completed`), as well as normalized contracts. Original fields remain retained provenance, not storage destinations.

The existing PrototypeImportBatch/Row entities hold source version/hash, row key, school/year/template, normalized source JSON, human mapping reasons, review digest/actor/time, commit actor/time, rowversion, verified bytes hash and S2 operation identity. Batch identity is source hash + school + year + template version; unique row keys complete the row identity. Source version is retained and a conflicting version label for identical bytes is rejected. SQL application locks serialize preview/commit and school+hash bytes, with separate sessions for S2 transaction compatibility. Existing S5 source-only rows remain readable as legacy references.

Preview writes only import ledgers. Mapping resolves existing S4 codes/SourceKeys and current real members; names are suggestions, never identities. No template/catalog duplication or automatic follow-up reassignment occurs. Changing mappings, requirements, membership or source invalidates the reviewed digest; stale rowversions fail. Committed mappings and source/bytes provenance are SQL-protected. Missing/new/conflicting entries have reasons and correction paths; published template changes require their existing version policy.

Metadata commit retains ReferenceOnly/Exception and exports every source row with its reason; reference rows cannot download or contribute files/approval/readiness. Source `completed` never becomes a review decision. Original bytes require a reviewed committed mapping, a current requirement, explicit reason, filename/extension/size matching and S2 validation (250 MiB). The durable reservation is keyed by school+SHA256. Uncertain responses reconcile the same provider identity; another actor cannot blindly replace a pending reservation. A round-trip download must match SHA256 before attaching independent **Draft** links. Only explicitly verified original bytes enter SchoolUpload with retained import provenance; protected HistoricalImport and VisitArchive remain excluded from general linking/readiness. No historical review decisions were invented.

Generic library downloads now recheck live access after provider I/O and persist `Storage.ContentRead`. If delegation is revoked during upload, the reservation/file is retained while linking/content disclosure fails. The disabled context checks the actual live school manager without requiring storage schema or contacting Google: the sidebar stays visible and the page links Google settings, while operational endpoints remain gated.
