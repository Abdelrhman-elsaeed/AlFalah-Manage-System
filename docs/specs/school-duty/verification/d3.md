## Delivered contracts

The three official forms use QuestPDF, actual Arabic shaping and the existing licensed embedded Amiri regular/bold fonts. Signed letter/report PDFs consume D2's existing `DutySignedDocument`; there is no second signing or submission workflow. Required snapshot/signature/logo evidence is checked before rendering. `UnavailableAtSigning` remains an empty historical logo position; no current remote branding is fetched. PDF bytes, SHA-256, renderer version and rendering provenance are frozen in `DutyPdfArtifact`. Later names, signatures, branding, enrollment, facts, corrections and assignment changes cannot rewrite retained bytes. Roster artifacts are bound to the published plan revision and create no archive intent.

The application owns document authorization, preparation, readiness and archive decisions. Infrastructure owns scoped queries, SQL locks and ledger persistence. Controllers remain thin and retain `ApiResponse<T>` for non-file results/errors. PDF responses use private/no-store, nosniff, sandbox and a retained SHA-256 header. Every read rechecks live school membership and actual author or authorized school-manager access; roster export has schedule-only access. Manager retry does not grant storage administration. Historical authors retain their own signed documents while remaining active in the original school, without access to the replacement's documents.

The manager's current document cards distinguish the replacement's current assignment from displaced signed history. History carries frozen author names, canonical duty dates, correction links/reasons and separate local/artifact/archive availability. Saved/submitted success survives disconnected archives. Local PDF reads do not call Drive. Submitted and historical documents appear near the top of the execution workspace; active draft editing and picker context are preserved.

`DutyArchive` folder kind (4) and file source kind (5) have independent identities and protection. They are excluded from ordinary storage/evidence/readiness projections and legacy teacher browsing, denied through general authenticated reads/mutations, and cannot enter evidence links or file-change workflows. Legacy administrator folder selection also hides/denies protected duty paths. The shared deny-only provider-ID query recognizes duty folders, reserved IDs and retained versions across schools, including externally moved files whose application properties were removed. No VisitId or evidence ownership is invented.

The protected hierarchy is school root / `المناوبات` / frozen academic year / term / actual teacher / canonical `yyyy-MM-dd`. Stable year/term/user/date identities determine folders; duplicate names receive a readable teacher-profile suffix. Reserved folder IDs are committed before creation. Signed corrections create immutable versions of the same two logical letter/report files; a delayed older revision cannot replace the latest pointer.

Archive operations retain school, assignment/revision, kind and unique signed submission ID, artifact hash, reserved provider ID, root/destination identity, SQL rowversion, leases, attempts and next-attempt state. Session SQL application locks fence competing workers; two-minute leases renew every twenty seconds. Transient failures use bounded exponential delays and stop after five attempts. Uncertain responses reconcile the same ID, metadata, full folder ancestry, properties, length and streamed SHA-256 before another write. SQL rollback after successful provider upload recovers without a second file/version. Completion requires verified output and committed ledger links. Provider doubles finish as `TestVerified`, never actual `Archived`.

Explicit archived reads verify provider bytes and return the retained immutable bytes. Worker reconciliation checks verified output after fifteen minutes; ordinary document listing uses the retained verification timestamp between reconciliations, keeping local navigation independent of repeated provider downloads. Missing/renamed/moved output is reported and never silently recreated after completion. Disconnection preserves local access.

## Readiness, safe activation and rollback

Defaults are safe: `SchoolDutyArchive:ProcessingEnabled=false`; each school's `SchoolGoogleDrive.DutyArchiveEnabled=false`. Pending D2 intents can still freeze local PDFs without external I/O. Local acknowledgement/report commits and internal guardian delivery remain independent of Drive.

Before any rollout, review the additive migration and apply it only through the separately authorized operational release process. Verify the existing school credential, root metadata/shared-drive identity and grant containment without changing roots/grants. A designated synthetic destination inside a verified authorized root and separate isolated SQL must be supplied before bounded live external verification. General provider access does not authorize writing into a real school's archive.

Once that gate and owner acceptance are satisfied, enable the process option through release configuration and enable only the intended school using authorized duty-manager `PUT /api/v1/school-duty/archive/enablement` with `{ "enabled": true }`. This validates the trusted root and rejects overlap with teacher grants. It does not enable visit archives or general storage administration. Existing Drive connection/root/credential changes revoke the duty enablement flag; it must be reviewed again. Readiness disabled/disconnected preserves pending intents and local documents.

Rollback sets the process option false and/or the intended school's duty enablement false. New external delivery stops; signed snapshots, lateness facts, internal notices, immutable PDFs, reservations and ledger history remain. Local PDF preparation/reads remain available. Do not run destructive Down, remove history, reset databases, delete provider data or re-sign/resubmit to retry an archive. Retry only the missing result through the duty-manager endpoint; retained reservations reconcile uncertainty first. Externally moved/renamed/missing completed artifacts require reviewed recovery, not an automatic new destination or ID.
