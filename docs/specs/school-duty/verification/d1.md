# D1 delivery and verification

**Date:** 2026-10-13. **Status:** D1 implemented; final client visual acceptance pending. D2/D3 remain unstarted. No production deployment or operational database migration.

## Delivered behavior

`/timetable` retains the existing timetable component and adds the duty workspace through accessible tabs. Existing editor, teacher views, clone/checkpoint/history, inline lesson swap, PDF/Excel, standby slots and daily lesson-cover implementations are retained. Duty deep links use `?tab=duty&date=YYYY-MM-DD`; tab switches retain the editor instance, and unsaved work prompts before leaving.

The actual current school manager selects active school teachers, searches the pool, orders the equal cyclic rotation, sets operating weekdays/date bounds, adds reasoned closure/exclusion ranges and restores eligibility. The server previews the exact distribution and future change range. Publication validates the preview digest, queue revision and request identity. Neither teaching load nor standby/lesson-cover counts weight the rotation.

Regeneration preserves past, locked, protected and exchange-related dates. Ordinary removed operating dates are canceled with original identity/history retained. A retained assignment that conflicts with new eligibility is an explicit review state. Settings publications preserve immutable settings snapshots; timetable clones never duplicate the duty plan. One plan per school/term and one stored duty identity per school/date prevent overlapping operational plans.

Staff attendance remains the secretary's existing workflow. Present is available; Absent/Excused is unavailable; no fact is unknown. Changed sheets save an attendance reconciliation signal with the facts in the same SQL transaction. A worker polls every ten seconds, processes current facts under the school queue lock, retries failures with bounded exponential delay and records completion. Reconciliation is independent of duty page visits.

For A's known absence, the next eligible effective future owner B takes D and A takes B's E. The exchange, both assignment revisions, evidence, history and notifications commit together. E is also durably requeued, so previously processed future attendance cannot strand repeated absence. A continued absence on E follows the current effective queue. Inactive, excluded, known unavailable and protected candidates are skipped. No substitute creates a visible manager exception; an eligible end-of-term cover without a usable E retains unresolved compensation. Unresolved obligations appear in later terms and can be assigned a reviewed real future date.

Corrected Present facts undo only the exact still-unmodified unlocked exchange pair. Otherwise the manager sees a correction review without silent reassignment. Manual replacement/exchange, compensation resolution and removal of protection require reasons and revision checks. The UI reviews before/after dates, warnings and fairness; an emergency absence/exclusion override requires explicit acceptance. Mixed mutation-mode IDs are rejected. Historical changes cannot be rewritten through EF or direct SQL.

Teachers receive a schedule-only projection with their own upcoming-date card. Manager settings, staff attendance facts/reasons, history and fairness are absent from their backend response. Public change labels describe schedule changes only; private attendance/compensation exception kinds are suppressed. Regeneration is labeled distinctly from an automatic absence exchange. Every operation derives school from the session and validates live school membership/permissions. Existing timetable/storage delegation does not grant duty access. The existing account signature-enrollment gate is retained; no D1 acknowledgement/report/signature endpoints are added.

Fairness focuses on selected teachers, retained allocation history and outstanding obligations, including ineligible historical owners. It omits unrelated zero-allocation staff. It displays original planned assignments, current effective assignments, currently allocated absence cover and pending compensation separately. Repeated moves do not create duplicate pending credit. Completed counts are zero until D2 supplies execution reports; a past date is not evidence of completed duty. Prior-term counts remain available through retained plans/term selection.

## Actual D1 API

All routes return the existing `ApiResponse<T>`. Expected errors carry stable codes: for example `DutyRevisionConflict`, `DutyIdempotencyConflict`, `DutyForbidden`, `DutyInvalidChange`, `DutyAttendanceCalendarMismatch` and `DutyNoEligibleTeacher`. Authorization is 403, unavailable in-scope identity 404, stale/idempotency conflict 409, invalid input 400.

| Method | `/api/v1/school-duty` route | Access / behavior |
|---|---|---|
| GET | `/context?termId=` | Live capability, scoped terms, schedule; manager additionally receives settings, teacher pool, staff status, history, fairness and retry count |
| POST | `/plans/preview` | Manager validates settings/range/revision and gets deterministic distribution, delta, fairness and warnings |
| POST | `/plans/publish` | Manager publishes reviewed settings/digest with request ID; same-content retry returns stored result |
| POST | `/assignments/change-preview` | Manager previews a reasoned replacement/exchange/protection/compensation decision |
| POST | `/assignments/change` | Revision-checked, atomic, idempotent manual decision |
| POST | `/reconciliation/retry` | Manager queues a fresh scoped reconciliation sweep; worker retry remains automatic |

The context is bounded by the selected term on the wire; it includes school-wide unresolved obligations for managers. Internal reconciliation reads the retained school queue and facts. This direct service/repository boundary follows existing modular-monolith conventions; no generic event bus or delegation engine was introduced.

## Schema and isolation

Non-destructive D1 migrations (no existing tables/columns/data are removed):

1. `20261013102255_AddSchoolDutyD1`: seven tables, scoped plan/term and participant identity keys, date/plan/request/signal uniqueness, queue concurrency tokens, permission catalog/grants and append-only SQL history trigger.
2. `20261013102540_AddDutySettingsHistory`: immutable settings-snapshot column.
3. `20261013104512_AddDutyTeacherSchoolIntegrity`: initial teacher school/profile integrity relationships.
4. `20261013113721_PreserveDutyHistoryAcrossTeacherTransfers`: replaces the D1-only mutable-school teacher FKs with stable profile/user identity and SQL scope validation on participant selection/assignment creation or ownership change. Original date/school/plan/teacher identity is SQL-immutable. Existing SQL-based profile transfers retain history; the baseline EF tracked-key restriction is unchanged.

All migration applications targeted fresh local databases named `AlFalahDutyTests_*`; fixtures reject other servers/catalog prefixes and check the master catalog before any migration, rejecting every existing database. A real SQL test verifies a rejected second initialization preserves migrations, assignments and history. The fixture first migrates to the pre-D1 schema, retains a sentinel school and encrypted-credential/root strings, applies all migrations twice and verifies preservation. No `appsettings*`, actual credential or operational key-ring changes were made. Synthetic live-smoke JWT settings/key directory exist only as child-process overrides.

## Reproduction

Use a **new** isolated database name for each SQL fixture run. Existing fixture databases are deliberately retained.

```powershell
$env:ALFALAH_DUTY_TEST_CONNECTION='Server=(localdb)\MSSQLLocalDB;Database=AlFalahDutyTests_NEW_NAME;Trusted_Connection=True;TrustServerCertificate=True'
dotnet test backend/AlFalah.Tests --filter 'FullyQualifiedName~Duty|FullyQualifiedName~Attendance|FullyQualifiedName~Timetable|FullyQualifiedName~Swap|FullyQualifiedName~Substitution|FullyQualifiedName~SignatureEnrollment' -m:1 /p:UseSharedCompilation=false
```

```powershell
cd frontend
npm run build -- --configuration development
node scripts/check-school-duty.mjs
npm test -- --watch=false --browsers=ChromeHeadless --ts-config=tsconfig.duty-spec.json --include='src/app/features/timetables/**/*.spec.ts' --include='src/app/features/intelligent-timetable/**/*.spec.ts' --include='src/app/shared/components/clearable-select/**/*.spec.ts'
```

The HTTP smoke harness accepts the same guarded LocalDB prefix and a workspace root argument. Build .NET projects sequentially to avoid file locks; then run `dotnet run --no-build --project docs/specs/school-duty/verification/live-smoke -- D:/AlFalah-Manage-System` with a fresh isolated connection. It starts a hidden child host on loopback 5387, uses synthetic process-only settings, checks the actual worker and stops its own host. Hosts/tests use .NET 8 targets with `LatestMajor` runtime roll-forward on this .NET 10-only machine. Never point the harness at an operational database.

## Genuine remaining limits and rollout

- Final client visual approval is pending the owner's review of the captures and interface.
- No original Development/production schema was migrated and no operational duty plan was published. Operational activation still requires normal review/backup/application of the four D1 migrations, permission refresh and initial manager configuration. This is an intentional boundary, not unverified live-school delivery.
- Broad backend failures: `StorageLibraryTests.Context_summary_uses_configured_root_without_waiting_for_Drive_health` fails with the existing offline fake Drive behavior; `SocialWorkerCrmRepositoryQueryTests.Case_messaging_queries_execute_relationally_and_enforce_scope_paging_and_confidential_projection` uses a SQLite fixture missing `ProtectedPassword`. Both were reproduced at HEAD `15037a3` in `D:/AlFalah-D1-Baseline` and left outside D1.
- Existing broad Angular specs call storage `ngOnChanges()` without its required argument and omit `ArchiveOperations.schoolEnabled`; they fail type checking before browser execution. Their source is unchanged from HEAD. The focused D1 configuration passes without editing them.
- Existing production stylesheet budgets fail for `storage-page.component.css` (39.34 kB against 32 kB) and `visit-workspace.component.css` (34.50 kB against 32 kB). Normalized source matches HEAD. Existing PrimeNG selector warnings remain. No unrelated styles or budgets were changed.
- D2 acknowledgement, saved-signature execution, reports, locks set by actual report activity, student lookup and completion proof are not delivered. D3 official PDFs/archive and live Google delivery are not delivered. Existing standby/daily lesson cover and its official-register follow-up retain their previous scope.
- Retry processing is durable and single-school serialized. A large retained school history may eventually require bounded internal SQL readers; D1 is not a claim of a measured large-scale performance rollout.

For rollback before operational activation, revert the D1 application changes. After activation, suspend new duty entry/worker/write access while preserving plans, history, receipts and attendance signals. Do not run destructive Down migrations or delete history to roll back. No production rollback/deployment was executed in this task.
