# D2 verification — Teacher execution and shared dismissal lateness

**Date:** 2026-10-13. **Scope:** Authorized D2 using C1–C17 and the relevant documented defaults. D1 remains implemented; D3 is not started. Final client visual acceptance remains pending owner review.

## Delivered behavior

The existing `/timetable?tab=duty` workspace now opens the actual teacher's own upcoming/history execution. Opening a responsibility letter is unsigned. Explicit acknowledgement and report submission apply the authenticated teacher's existing saved handwritten signature. Managers can review, authorize corrections and handle emergencies, but cannot sign as a teacher. Missing-signature setup returns to the same duty draft through the existing account screen.

Drafts persist on the server with an incrementing expected version and real save timestamp. Editing during an outstanding save preserves subsequent input. A failed save retains session input; a conflict shows local/current observations and departure values for deliberate resolution. Unsaved navigation is guarded. Submission replays its durable request receipt after a lost response instead of signing twice. Signed documents retain signature PNG bytes/SHA-256, snapshot SHA-256, signing/account timestamps, author/display identities, school/year/term/date, original/effective teacher, signature position, assignment revision/history, source template version and timing evidence. Profile/signature changes never rewrite signed history. Local signing commits an archive intent in `PendingD3`; it performs no PDF/Drive operation.

Emergency replacement uses D1's reviewed manual-change flow with a compulsory reason and explicit exception acknowledgement. It retains signed letters/reports and each displaced draft in append-only change history, including A → B → A ownership. The replacement must acknowledge with their own signature. Draft/letter/fact/report activity locks the assignment against silent attendance reconciliation or regeneration. Manager corrections retain prior signed documents and require the actual current teacher's re-signature; timing/fact corrections also open a reasoned correction draft when necessary.

Student selection uses the whole school's active term enrollment through a narrow authorized DTO: student/enrollment/class IDs, name, school number, class and grade. No contacts, national identity or unrelated profile/case fields are exposed. Server search, grade/class filters, grouped results, classroom navigation and 24-row paging support repeated entry with retained context and duplicate-name disambiguation. Invalid/departed roster entries require enrollment resolution; there is no manual-name fallback. Phone dialogs use available visual viewport height, fixed selection/confirmation footers, visible focus and explicit Escape/focus-return handling.

Explicit lateness confirmation commits one stable school/student/date fact, retained revision/audit and durable communication intent in the same serializable school transaction. Search, selection and autosave never notify. Facts retain author/current assignment revision, local observation, frozen dismissal/bell/timezone reference, action/notes and optional known departure. There is no invented grace period, departure or delivery. When departure is known, the notice states the recorded departure time and does not ask the guardian to arrange an already completed pickup. Student records and manager statistics appear before final report signing and before notice delivery. Retraction changes active counts without erasing history; correction notices retain revision linkage. Morning/lesson delay, absence and disciplinary counters are independent.

The hosted internal worker creates actual guardian-dashboard content and an actual message in existing Messages for each effective, notification-enabled, active linked guardian. It creates no fake staff account: System messages have a null human sender and server-owned provenance. Each guardian gets a confidential read-only System thread. Browser send contracts reject origin forgery; normal human send permissions and office hours remain intact. One fact/revision/recipient correlation joins the two surfaces, while delivery and read receipts are independent. A successful surface is never resent just because the other failed. Missing guardian, pending, retry and attention states remain truthful; current guardian scope is checked again before delivery and reading. No duplicate generic new-message/dashboard alert is emitted.

The existing manager overview contains today's dismissal count and a date/term/class-filtered paginated names drill-down, with distinct students and incident totals for ranges. The previously empty student timeline projection now reads real retained lateness revisions. The existing student analytics profile includes these events and a separate dismissal count. Existing full-record permissions remain unchanged: the manager's aggregate-only boundary is preserved, while authorized student-affairs staff can open the full student record.
