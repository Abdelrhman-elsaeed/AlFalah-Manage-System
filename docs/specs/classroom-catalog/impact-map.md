# Current-system impact map

Read-only repository review,2026-10-15. Paths below are relative to the repository root. Statements describe inspected code, not assumptions about an operational database. The repeatable [source inventory](verification/source-inventory.json) captures paths, matching lines and file hashes:220 runtime files,53 tests,5 fixtures/seeders and76 migration files. Lexical discovery is a search aid, not a claim that every match needs editing or that semantics can be proven by regex.

## Three different relationships exist today

| Concept | Actual representation | Consequence |
|---|---|---|
| School classroom section | `Classroom`: SchoolId,AcademicYearId,Stage,GradeLevel,Section,ClassLabel,PhysicalLocation,activity/audit | A usable shared catalogue already exists; do not replace its IDs. |
| Teacher's declared classes | `InstructorClass`: InstructorProfileId,free-form ClassLabel,SortOrder,soft deletion | No classroom/year foreign key. Repeated labels can disagree with the catalogue and rename breaks text matching. |
| Official subject allocation | `ClassSubjectRequirement` → `TeachingAssignment` → members of a setup-bound `TeacherTimetableProfile` | Already links ClassroomId and SubjectId; retain allocation, capacity, pairs, revision and logical occurrence rules. |

The current classroom uniqueness constraint is `(SchoolId,AcademicYearId,ClassLabel)` for nondeleted rows. It does not prevent two differently named rows representing the same grade/section. The classroom validator accepts grade1–12 without a stage-specific range. Manager create accepts both `Section` and arbitrary `ClassLabel`. Intermediate seed data already uses local grades1–3 and letter sections; there is no evidence supporting a global subtract-six conversion.

## Source completeness check

Run `python docs/specs/classroom-catalog/scripts/audit-classroom-surfaces.py` to regenerate the file/line/hash inventory. It scans backend and frontend application code; tests, fixtures and migrations are classified separately. The semantic table also includes the account/user paths whose public field is only named `classes`, and export/layout concerns not discovered by a simple ClassroomId search. Future implementation must rerun the scan and classify every remaining active text-identity comparison as either removed, an explicit bounded import compatibility adapter, or a historical snapshot. Unclassified authorization/name comparisons block cutover.

No operational SQL query was executed in this discovery phase. Therefore actual duplicate counts, orphan labels and migration match percentages are **unknown**; obtaining them is a read-only deliverable of the future migration phase, not a result claimed here.
