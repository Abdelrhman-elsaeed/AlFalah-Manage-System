| D-24 | 2026-07-10 | Backend/Security | **CRITICAL security hot-fix — end-to-end school-scoping in Phase 2 services (post-Phase-3, pre-Phase-4)**. **Bug reproduced**: `school_manager_1` (Ahmed Al-Omry, `ActiveSchoolId=1`) could see all 6 schools via `GET /api/v1/schools`, all 5 assignments via `GET /user-school-roles`, and leak school-8 (اسكول تيست) rows via `?schoolId=8` — manual test confirmed by the user. **Root cause**: Phase 2 services (`SchoolService` / `UserService` / `UserSchoolRoleService`) trusted client-supplied `schoolId` parameters and never consulted `ICurrentUserService.ActiveSchoolId` — exactly the failure mode that [docs/08-SECURITY.md](../08-SECURITY.md) ("school-scoping enforced in the backend, never trust frontend filtering") and the constitution (`School-scoped queries enforced in the backend`) explicitly warn against. **Fix** (additive, no migration, no Phase 4 work): (a) New `ICurrentUserService.IsGlobalAdmin()` + `IsSchoolScopedRole()` helpers driven by JWT `Role` claims (also exposes `RoleNames` constants).
